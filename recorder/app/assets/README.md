# Clipwise icon assets (SAA-130)

Everything here is generated by `render.swift` from one source of truth,
`clipwise-mark.svg`. Regenerate with:

    cd recorder/app/assets
    swiftc -O render.swift -o render && ./render
    iconutil --convert icns Clipwise.iconset --output Clipwise.icns

`render.swift` refuses to run if `clipwise-mark.svg` no longer matches the
geometry compiled into it, so the two cannot drift apart silently.

## Source

`clipwise-mark.svg` is a byte-for-byte copy of the repo's `favicon.svg`, which
is in turn identical to both inline copies in `index.html` — verified, not
assumed. It is a true vector: an orange `#F4620A` rounded tile, four white bars
at descending opacities, and a `#F5C842` dot. Nothing here is upscaled from a
raster.

There is no SVG rasteriser on this machine (no `rsvg-convert`, no Inkscape, no
Pillow), so `render.swift` redraws the mark in CoreGraphics from the SVG's
numbers rather than converting the file.

## App icon

`icon-1024.png` plus `Clipwise.iconset/` (the ten standard entries, 16 through
512 at @1x and @2x) and `Clipwise.icns` built from it.

The tile is drawn on the Big Sur grid: 824/1024 of the canvas, centred, the rest
transparent. An icon drawn edge to edge reads a size larger than everything
beside it in the Dock.

Wired into `build-app.sh`, which copies the `.icns` into `Resources/` and sets
`CFBundleIconFile`. Before this the bundle shipped with no icon at all.

## Tray marks

`tray/` holds two complete variants of all four states `iconFor` renders, at
16pt @1x and @2x:

  * `<state>Template.png` / `@2x` — monochrome, shape carried entirely in alpha.
    The `Template` suffix is the macOS convention: AppKit and Electron both
    treat an image named that way as a template and invert it per background.
  * `<state>.png` / `@2x` — fixed colour, using the same dot palette
    `main.js`'s `DOT` table already uses.

The tray mark drops the tile. A 16pt orange square with four bars inside it is
a blob, and a coloured tile cannot be a template image.

State is encoded on two channels, so it survives monochrome where hue does not
exist:

| state     | bars   | dot    |
|-----------|--------|--------|
| stopped   | flat   | none   |
| starting  | flat   | ring   |
| recording | varied | filled |
| stalled   | flat   | filled |

Recording is the only state with varied bars, because recording-or-not is the
distinction that has to be readable without comparing against anything.

**Nothing in `main.js` uses these yet.** `iconFor` still generates its coloured
dot at runtime. Choosing between the two variants is a design decision that has
not been made, and wiring one in would make it silently.

## Preview

`preview/tray-preview.png` — every state, both variants, at true 16 and 32
device pixels, on light and dark menu bar backgrounds, with drawn neighbour
glyphs at the same scale for weight comparison. Nothing on the mark path is
scaled. The neighbours are drawn rather than screenshotted so the sheet carries
none of whatever was on the real menu bar at the time.
